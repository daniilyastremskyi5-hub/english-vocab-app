## Ответы на вопросы

**1. Сломает ли это текущую логику разбора и записи в историю?**
Нет, если делать аккуратно. Вся логика разбора (`run()` в `src/routes/index.tsx`, ~строки 1448–1655) включая запись в `history`, кэш, рендер Light/Full, обработку Cyrillic/sentence/context — остаётся нетронутой. Меняется только триггер: вместо клика по `#goBtn` функцию вызывает чат. История продолжит работать так же — она пишется внутри `run()` через `addHistory()`.

**2. Сможет ли чат вызывать ту же функцию разбора?**
Да. Сейчас `run()` объявлена внутри `useEffect` и недоступна снаружи. Нужно её экспонировать наружу — самый простой и безопасный путь: повесить на `window` (например `window.__lnRunBreakdown(query, context?)`). `AssistantSidebar` будет вызывать этот метод, когда Claude вернёт намерение «разобрать слово/фразу».

**3. Риски**
- **Распознавание намерения**: ассистент должен надёжно отличать «разбери X» от обычного вопроса. Решение — структурированный ответ Claude (JSON с полем `action: "breakdown"` + `query`, `context`), либо tool-call. Без этого будут ложные срабатывания.
- **Текущее слово в контексте чата**: `getPageInfo()` читает `#results` и `#input.value`. После удаления поля ввода `currentWord` будет браться только из `.word` в результатах — это ОК, но надо проверить.
- **Cyrillic-режим, sentence, context, повторный поиск из истории/папок**: всё это сейчас идёт через `run()` + `input.value = ...`. Нужно убедиться, что `window.__lnRunBreakdown` поддерживает все три режима (просто принимает `q` и `ctx`).
- **Пустое состояние**: после удаления формы при первом заходе экран будет пуст — нужно осмысленное empty-state с подсказкой «спросите ассистента справа».
- **Мобильный layout**: сейчас сайдбар ассистента 360px справа. Если поле ввода исчезает, на мобильных весь ввод уходит в чат — нужно проверить, что чат на мобилке не схлопывается в FAB по умолчанию (сейчас default open).
- **Шаги из существующего UI**, которые подставляли `input.value` (клики по словам в разборе, history, words) — их нужно перевести на тот же `window.__lnRunBreakdown` вместо `input.value = w; form.submit()`.
- **SSR/типы**: `window.__lnRunBreakdown` нужно типизировать через `declare global`.
